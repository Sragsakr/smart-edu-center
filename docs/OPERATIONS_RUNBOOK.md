Status: **OPERATIONAL CONTRACT** — المرجع التنفيذي لـ`P01-11` و`P01-12` و`P01-13` و`P01-15`.

## 1. النسخ الاحتياطي (`P01-11`)

### الأمر

```bash
export DATABASE_URL=postgresql://<user>@<host>:<port>/<db>
export BACKUP_DIR=/mnt/offsite/saboraty-backups   # وجهة خارج السيرفر
export BACKUP_ENCRYPTION_KEY=<at least 16 chars>  # من مدير أسرار البيئة، لا في Git
export BACKUP_RETENTION_DAYS=14
npm run backup:database
```

### ما يضمنه السكربت

| الضمان | كيف يُفرض |
|---|---|
| لا نسخة غير مشفّرة في الوجهة | التشفير يحدث في مجلد مؤقت، والمكتوب في `BACKUP_DIR` هو الملف المشفّر فقط |
| لا تشغيل بلا مفتاح | رفض فوري إن غاب `BACKUP_ENCRYPTION_KEY` أو قلّ عن 16 حرفًا |
| المفتاح لا يظهر في سطر الأوامر | يُمرَّر عبر ملف بصلاحيات `0600` لا كوسيط |
| الوجهة ليست محلية فقط | رفض إن غاب `BACKUP_DIR`، برسالة تشرح أن النسخ المحلي لا يكفي |
| النسخة قابلة للفتح فعلًا | فك تشفير فوري ومقارنة `sha256` قبل اعتبارها صالحة |
| الأثر قابل للتتبع | سطر في `manifest.jsonl` يحمل الاسم والبصمة والحجم والزمن |
| التقليم محدود | `BACKUP_RETENTION_DAYS`، ولا يُحذف أي ملف لا يطابق صيغة النسخ |
| الفشل ظاهر | رسالة `BACKUP FAILED: ...` ورمز خروج غير صفري |

### الجدولة المطلوبة

نسخة يومية على الأقل في وقت انخفاض الاستخدام، ووجهة **خارج نفس السيرفر/المزوّد**. الجدولة نفسها خطوة بنية تحتية تحتاج تنفيذ المالك (cron على مضيف النسخ أو مهمة مجدولة في Coolify).

## 2. تجربة الاستعادة (`P01-12`)

### الأمر

```bash
export BACKUP_DIR=/mnt/offsite/saboraty-backups
export BACKUP_ENCRYPTION_KEY=<same key>
export RESTORE_DRILL_DATABASE_URL=postgresql://<user>@127.0.0.1:5433/saboraty_restore_drill
npm run restore:drill
```

### حراسة إلزامية قبل أي استعادة

يُرفض التشغيل فورًا إذا:

- غابت `RESTORE_DRILL_DATABASE_URL` (لا تخمين لقاعدة هدف).
- كان اسم القاعدة `saboraty` أو `postgres` أو `template0/1`.
- طابق الهدف `DATABASE_URL` ولو بصيغة مختلفة لعنوان الاتصال.
- كان المضيف غير loopback.

### ما تتحقق منه التجربة

1. بصمة النسخة المفتوحة تطابق إفادة الـmanifest.
2. الاستعادة الفعلية عبر `pg_restore` بلا مالك ولا صلاحيات موروثة (قابلة للنقل بين البيئات).
3. كل فحوص الـbaseline بعد الاستعادة (`clean-baseline-smoke.sql`).
4. **الهوية تعمل:** كلمة مرور Platform Admin تُتحقق بـمُتحقّق التطبيق نفسه.
5. **تخزين البصمات فقط:** صيغة `password_digest` هي `scrypt-v1$…`، و`token_digest` بصمة sha256 — لا سرّ خام.
6. **العزل سليم:** محاولة إدخال طالب من مساحة على فرع مساحة أخرى تُرفض.
7. **الاستحقاقات محفوظة:** كل مساحة ما زالت تحمل قدرات مستواها.

### النتيجة المسجلة (2026-09-11، محليًا)

```text
restored to: saboraty_restore_drill
smoke:       46/46 checks passed
auth:        password verifies = true, digest-only storage = true
sessions:    12 restored row(s), all digest-shaped
isolation:   cross-tenant insert rejected = true
entitlements:{"teacher":15,"center":10}
RTO:         0.3s
RPO:         0s   (نسخة أُخذت قبل التجربة مباشرة)
```

وشُغّلت التجربة أيضًا على نسخة عمرها 121 ثانية، فسجّلت `RPO: 121s` — وهو الرقم الأصدق لقياس الفجوة الزمنية عند عدم أخذ نسخة قبل التجربة.

**قراءة الأرقام:** `RTO` هنا زمن الاستعادة نفسه، وليس زمن التعافي الكامل المتوقع في حادثة حقيقية (يشمل قرار التعافي، وإعادة نشر التطبيق، والتحقق). أما `RPO` فهو عمر آخر نسخة، ويتحسن بزيادة تكرار النسخ المجدولة.

### الدورية

تجربة استعادة **شهرية** على الأقل، وإلزاميًا بعد أي تغيير في المخطط أو في مزوّد الاستضافة. `P16-06` يرفعها إلى ربع سنوية آلية مع تحقق آلي من النسخ.

## 3. المراقبة (`P01-13`)

### ما يعمل اليوم

| المكوّن | الحالة |
|---|---|
| `GET /api/health` | يفحص الاتصال بقاعدة البيانات: `200` أو `503`، بلا كشف تفاصيل |
| `GET /api/readiness` | يفحص الاتصال + وجود كل جداول الـbaseline: `200` مع `schema: ready` أو `503` |
| سجل منظم منقّح | `src/lib/observability/server-logger.ts` يكتب JSON سطرًا واحدًا إلى stdout/stderr، وكل سياق يمر على `redact-pii` |
| حجب البيانات الشخصية | `src/lib/observability/redact-pii.ts` يُخفي البريد والهاتف والرموز وبصمات الجلسات وسلاسل الاتصال، **ويحتفظ بـUUID والطوابع الزمنية** حتى تبقى السجلات قابلة للربط |
| فحص الاعتماد المتقاعد | `npm run check:runtime-dependencies` يمنع رجوع Supabase/Vercel إلى الـruntime |

### ما يحتاج تنفيذ المالك (خارج الكود)

- **مراقبة توفّر خارجية** على `/api/health` و`/api/readiness` من خارج الشبكة، مع تنبيه عند الفشل المتكرر.
- **لوحة موارد**: CPU / RAM / disk / اتصالات قاعدة البيانات.
- **استلام السجلات**: التأكد أن Coolify يجمع stdout/stderr ويحتفظ بها مدة كافية.
- **مزوّد تتبّع أخطاء** (Sentry أو بديل): القرار مؤجل حتى وجود حاجة مثبتة. عند إضافته يجب أن يمر عبر نفس التنقيح، وأن تكون الـDSN في متغير خادمي فقط.

### شكل السجل

```json
{"level":"error","event":"workspace_request.approve_failed","message":"duplicate key value violates unique constraint","timestamp":"2026-09-11T18:00:00.000Z","context":{"requestId":"…","reviewerId":"…","errorId":"Error"}}
```

المعرّفات تبقى ظاهرة ليمكن تتبّع الحادثة، وبيانات مقدّم الطلب محجوبة.

## 4. Rollback وCutover ونهاية العمر (`P01-15`)

### مبدأ عام

لا تُحذف بنية قديمة قبل إثبات أن البديل يعمل وأن نسخة الاستعادة صالحة. الترتيب دائمًا: **أثبت ثم انقل ثم أزل**.

### عند فشل نشر على Staging

1. أعد نشر آخر إصدار ناجح من نفس الفرع (Coolify يحتفظ بالإصدارات).
2. تأكد أن `/api/health` و`/api/readiness` عادا `200`.
3. لا تبنِ على الفشل: سجّل السبب وأصلحه في فرع جديد.

### عند فشل تغيير مخطط

1. أوقف الكتابة على البيئة المتأثرة.
2. استعد آخر نسخة سليمة بقاعدة تجربة استعادة **قبل** لمس البيئة الحقيقية.
3. أعد تطبيق الـbaseline الحالي، ثم أعِد الـseed إن كانت البيئة تطويرية.
4. سجّل السبب والزمن و`RPO` الفعلي.

### شروط إزالة البنية القديمة (decommission)

لا تُنفَّذ إلا بعد تحقق **كل** ما يلي:

- [ ] الـbaseline الحالي مطبّق على كل البيئات، و`/api/readiness` يعيد `ready`.
- [ ] تجربة استعادة ناجحة من نسخة حديثة على بيئة معزولة.
- [ ] صفر اعتماد على المزوّد القديم في الكود (`check:runtime-dependencies` ناجح في CI).
- [ ] لا تشير أي متغيرات بيئة إلى موارد قديمة.
- [ ] إعلان المالك يعني أن حذف المورد القديم مقصود ومسجّل.

### حالتنا الحالية

- بنية Supabase القديمة: **لا اعتماد runtime** عليها، والملفات التاريخية محفوظة للقراءة فقط في `postgres/reference/`.
- **إجراء مطلوب من المالك:** تدوير المفاتيح التي ظهرت في إعداد محلي متقاعد، ثم حذف ذلك الملف. التدوير هو الإجراء الأمني الفعلي، ولا يستبدله حذف الملف.
- بيئة Vercel: غير مرتبطة بالمستودع ولا تدخل في مسار النشر.
